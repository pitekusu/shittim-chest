# Scale-to-Zeroの導入順序

[文書索引へ戻る](../00_シッテムの箱_ドキュメント索引.md) · [導入の到達点](10_scale-to-zero-goal.md)

> 完了した導入の経緯である。現在のPR分割、配信承認、再試行の作業指示ではない。

## 当時の依存順序

| 順序 | 追加したもの | 次の段階へ渡した境界 |
|---|---|---|
| 1 | SDKに依存しない状態・稼働・所有者の世代 | 処理を再開・停止する条件 |
| 2 | DynamoDB保存形式・トランザクション・処理権・待ち行列 | 永続化された受付と排他制御 |
| 3 | 署名付きHTTP受付・状態通知 | タスク停止中の受付 |
| 4 | 実行環境の調整とECS 0/1制御 | 保存済み作業に応じた起動 |
| 5 | プロセスの起動・復旧・終了・ヘルスチェック | 中断後も再開できる実行環境 |
| 6 | CDK・権限・監視・費用管理 | 本番のリソース所有と観測 |
| 7 | 配信ロック・変更計画・スモークチェック・後片付け | 承認した構成だけの適用 |
| 8 | 実利用の受入と発見した障害の是正 | 運用への引き継ぎ |

## 現在の変更へ引き継ぐこと

実装・試験・文書・配信証拠の対応を保つ。イメージを変えた場合は、その実行回の本番用成果物を検証する。
失敗時は実行済みの変更と後片付けを確認し、状態を確認せずに再実行しない。

現在の進め方は[19 実装との対応](../19_実装計画・トレーサビリティ.md)、配信は
[15 CI/CD](../15_GitHub・CI-CD詳細設計.md)、障害対応は[17 運用](../17_運用保守・監視・障害対応設計.md)を正とする。

旧コミット分割、担当者向けの再開指示、試行ごとの記録はGit履歴へ残す。
本書へ新しい実装計画を追記しない。
