## 解決した問題から残す設計上の対策

個別の調査ログではなく、今後も維持すべき対策だけを残す。

| 問題 | 原因 | 現行設計に残した対策 |
|---|---|---|
| Discord初回応答の遅延 | コールド起動が応答期限を超えた | HTTP受付、短い初回応答、対応LambdaのSnapStart |
| 遅れた状態通知の取り違え | 複数の議論に共通する状態への更新 | 議論・試行ごとの排他情報と終了状態への収束 |
| 送信済み投稿の確定停滞 | Discord送信直後の保存がハートビートと競合した | 既知の投稿IDと確定時刻を保持し、再投稿せず確定処理だけを再試行 |
| 帰宅の挨拶の欠落 | 停止直前の実行と過剰な情報源照合 | 停止前の独立処理、出典条件の明確化、上限付き再試行 |
| Outbox監視値の欠測 | EMFがログの文字列フィールドへ入った | CloudWatchが抽出できるルートJSON形式で出力 |
| 当日の概算費用が0円 | 当日為替の公開前にも完全な期間データを要求した | 当日だけ直前の有効レートで暫定換算し、一部未確定と明示 |
| Records初回配信の競合 | ロググループの所有と名前が重複した | 明示的な所有先、削除前の対象確認、独立した復旧手順 |
| 共有スキーマ移行前の配信停止 | 旧版の管理レコードを新版だけで検証した | 均一な旧版・新版を検証し、管理レコード移行とロック取得を原子的に実行 |
| Coreへ公開ホスト名が渡らない | GitHubがジョブ出力を機密候補として抑止した | 同一コミットの署名済みRecords配信記録を同梱し、適用側で再検証・直接参照 |
| イメージ内部値の不一致 | ビルドへの一時ファイル混入、実行回をまたぐ固定値照合 | 清浄なコミットからのビルド、同一実行回の成果物と証拠の照合 |
| 署名関連の過去証跡の数え過ぎ | 同一ダイジェストに付いた以前の証跡も数えた | 今回追加された有効な参照との差分を検証 |

調査・復旧の手順は[17 運用・障害対応](17_運用保守・監視・障害対応設計.md)へ集約する。
